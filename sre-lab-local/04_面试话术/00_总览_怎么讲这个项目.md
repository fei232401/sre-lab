# 00 总览:怎么讲这个项目

> 这份解决一个问题:**面试官问"介绍一个你做的运维项目",你从哪句开始说。**
>
> 教材(`07_标本教学/`)解决"我怎么理解它";这份解决"我怎么把它讲出去"。两者用同一批事实,但**组织方式相反**:教材是横切面(九段传送带、八道接缝),这里是纵切面(一次完整的推送)。

---

## 一、先定调:这个项目的一句话是什么

**不是"我搭了一套 CI/CD",而是:**

> **"我把一条从代码到线上 Pod 的链路完整地跑了一遍,然后发现——这条路上最危险的问题,全都是不报错的。"**

这句话是整份话术的锚。**它决定了你后面所有故事的方向**,而且是面试官很难反驳、又很容易顺着往下问的一句。往下问什么?问"什么叫不报错"。而你手上正好有五个真实案例(见 `02_深挖弹药`)。

### 三个长度的版本

**30 秒(自我介绍里带过)**

> "我自己搭了一套本地的 SRE 实操环境:k3d 三节点集群,CI 用 Jenkins 跑在集群里,代码托管用集群内自建的 Gitea,GitOps 用 ArgoCD 管六个应用,监控是 Prometheus + Loki + Alertmanager。我完整跑通了从 `git push` 到集群收敛到你真能看到新版本在跑的全过程。但我觉得这个项目真正有价值的地方不是搭起来了,而是**我在上面踩到的坑**——那些坑有个共同点:**它们全都不报错**。"

**2 分钟(面试官说"详细讲讲")**

在 30 秒的基础上展开三段:

1. **链路是什么**:push 到 Gitea → webhook 触发 Jenkins → 构建镜像(打上 git 短 SHA 作为 tag)→ 推到本地 registry → 流水线把新 tag 写回 GitOps 清单 → ArgoCD 收敛 → 新 Pod 起来
2. **我做了一件多余但关键的事**:让程序通过 `/metrics` **自报版本号**(构建期把 git SHA 注入镜像)。这样"跑的是哪个版本"不是看 Pod 上的 tag 字符串,而是**从容器内部经真实数据面取回来的**
3. **然后我在这条链上抓到的坑**:一句话带三个——CI 静默不触发、Gitea 拒绝投递 webhook、ArgoCD 秒级拉回手工改动。**三个的共同形态:命令成功、面板全绿、事情没发生**

**5 分钟(面试官明显有兴趣)**

2 分钟版 + **完整讲一个案例到底**(推荐讲"CI 静默不触发",见 `02_深挖弹药` 第一条),包括:

- 现象(推了代码 6 分钟没动静,所有面板全绿)
- 我怎么定位的(**`Took 2 ms` 这个数字物理上不可能**)
- 我下过的**错**结论,以及它被什么证据推翻
- 最后换成 webhook,以及为什么 webhook 不只是"换个触发方式"——**它给了轮询结构上给不了的东西**(推送的 `before`/`after` 两个 revision)

> **5 分钟版里一定要包含"我下过错结论"这一段。** 这不是减分项——**面试官真正想确认的是"你判断错了之后,会不会自我纠正"**,而不是"你能不能一次就对"。而且这段能自然地把话题引到你最熟的地方。

## 二、"这个项目最难的地方是什么?"

**不要答"环境搭起来很麻烦"。** 那是工作量,不是难度。三个可选的答法,按你想把话题引向哪里挑:

### 答法 A → 引向"静默失效"(推荐)

> "最难的不是让链路通,是**知道它什么时候不通了**。这条链上有好几个环节的失败形态是'什么都不发生'——没有报错、没有告警、监控面板全绿。而'什么都没发生'和'本来就没事'在监控上长得一模一样。**所以后来我在这条链上做的每一处改动,验收标准都不是'它能不能跑通',而是'它坏了的话,我多久能知道'。**"

### 答法 B → 引向"声明式与命令式的冲突"

> "难在我得**改掉自己的肌肉记忆**。我做了很多年命令式的操作——服务不对了就上去 `kubectl` 改一下。但在 GitOps 里,手工改动是**无效动作**:我实测过,手工把镜像换掉,**5 秒后就被 ArgoCD 拉回去了**。而且它不报错,命令返回成功、`kubectl get` 头两秒也确实显示新值。**如果我只看那两秒,我会得出'改成功了'的结论。** 这件事让我重新理解了'声明式'——它不是一种写法,是**权力的转移**:期望状态归 Git,不归我。"

### 答法 C → 引向"可验证性"

> "最难的是**怎么证明一件事真的发生了**。我们习惯用过程指标来证明——流水线绿了、Pod 是 Running、`rollout status` 说完成了。但这些都只证明'流程走到了这一步',不证明'结果达成了'。所以我给 exporter 加了一个自报版本号的指标:**部署之后,这个指标得出现,而且版本号得对得上**。这不是锦上添花,这是把'我以为成了'变成'我能证明成了'。"

> **如果面试官追问"那你怎么保证你说的这些不是编的"**——这是好问题,大方接:
>
> "我全套记录都在仓库里,而且**该标'待核实'的地方我都标了**。比如有个结论我后来发现说大了,当场就在文档里写了一节把自己推翻——因为那条推断我没有做受控实验去证伪它。**我觉得一个运维文档里如果一条'待核实'都没有,那反而说明写的人没在认真区分'我知道'和'我以为我知道'。**"

## 三、诚实边界:主动说,别等被问

**主动交代边界不会减分,反而会让人觉得你清楚自己做了什么。** 这几条按场合挑着说:

| 边界 | 怎么说 |
|---|---|
| **本地实验环境,不是生产** | "这是我本地一台机器上的 k3d 集群。它的价值不在规模,在于**该有的接缝一个不少**——声明与收敛、凭据、观测、回滚,这些在单机上和在集群上没有本质区别。" |
| **Git 跑在集群里,不是集群外** | "我为了绕开外网的不稳定,把 Gitea 建在了集群内。**严格说我动摇了'Git 是集群外唯一真相来源'这个前提**——真正的生产形态是 Git 在集群之外。这是本地资源约束下的折中,不是我认为它更好。" |
| **有配置不在版本控制里** | "Gitea 的 webhook 定义、Jenkins 里那个 webhook 令牌、Gitea 自己的 `app.ini`,这三样**不在 Git 里**,集群重建会丢。我如实记在手册里,**没有假装它是 IaC**。而且这三样丢了**不会报错,只会让链路安静地不动**——正好又是我前面说的那个模式。" |
| **没有 HA、没有多集群落地** | "单副本,没有高可用;多集群我做了设计分析但没落地。我能讲清楚多集群的**分叉点在哪、为什么不是复制粘贴**,但**我不会说我已经做过了**。" |

## 四、面试官可能从哪几个方向切进来

知道他从哪儿切,你就知道该往哪儿接:

| 他问什么 | 他想确认什么 | 你接哪儿 |
|---|---|---|
| "Jenkins 和 ArgoCD 都管部署,不重复吗?" | 你分不分得清 CI 和 CD | 分工:**Jenkins 只负责产出制品和改声明,ArgoCD 只负责让集群收敛到声明**。CI 不碰集群 |
| "为什么不用 GitLab CI / GitHub Actions?" | 你选型有没有理由 | 环路的稳定性:外网的可用性不由我控制(见 `01_故事线` 的 DNS 那段) |
| "出过什么事故?" | 有没有真踩过坑 | 直接进 `02_深挖弹药` |
| "回滚怎么做?" | 有没有想过失败路径 | `git revert` 改声明,不是 `rollout undo`。**附带讲:回滚后的证据是"新指标整行消失"** |
| "PV/PVC、网络、存储?" | 基础扎不扎实 | 这块别硬撑,会什么说什么 |
| "你觉得自己最弱的是什么?" | 自我认知 | 照实说(比如 K8s 网络/CNI 深度不够),接一句"所以我现在在补的是 X" |

## 五、千万别踩的三个雷

1. **别把"搭起来了"当卖点。** 搭一套 Jenkins + ArgoCD 是教程级的活,**任何跟着文档走的人都能做出来**。你的差异全在"踩到并定位了别人不一定会踩的坑"。

2. **别把所有事说得太顺。** 全程"我一看日志就发现了"是最假的一种叙述。**留一两处"我一开始判断错了"**,可信度会立刻不一样——而且你手上真有素材。

3. **别用没验证过的具体数字。** 说"我这边收敛大概一两分钟"可以;说"37 秒"就危险了,除非你手上真有那次记录。**面试官追问一句"怎么测的",编的数字是撑不住的。**
